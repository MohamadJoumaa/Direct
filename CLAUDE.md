# Direct — project memory

Lebanese same-city delivery app. Send a package, watch the driver on a live map, pay cash on
arrival, both sides confirm the handoff. Four roles share one web app: **admin, client, business,
driver**.

Phase 1 is the Next.js website. Phase 2 is the Expo app in `apps/mobile` — all four roles, sharing
every domain rule with the web. Both clients still run on the demo store; the Supabase cutover
(Phase 2 Workstream A) is not done.

---

## Commands

Run everything from the repo root. Node >= 20.

```bash
npm install
npm run dev          # @direct/web on http://localhost:3000
npm run build        # next build
npm run lint         # eslint (flat config, eslint-config-next)
npm run test:shared  # node --test on packages/shared (31 tests, all passing)
npm run db:reset     # npx supabase db reset (schema only — the UI does not read Supabase)

npm run mobile       # expo start (Expo Go or a dev build)
npm run mobile:ios   # iOS simulator (macOS only)
npm run mobile:android
npm run mobile:web   # browser preview of the Expo app — review only, not a target
npm run typecheck:mobile
```

**Adding a shared test file requires editing `packages/shared/package.json`** — the `test` script
lists test files explicitly (`node --experimental-strip-types --test src/a.test.ts src/b.test.ts …`);
there is no glob.

`.claude/launch.json` defines a `direct-web` preview config on port 3000.

## Layout

```
apps/web              Next.js 16 App Router UI — the Phase 1 product
apps/mobile           @direct/mobile — Expo SDK 57 app, all four roles (Phase 2)
packages/shared       @direct/shared — pure domain rules (pricing, dispatch, payment, subscription)
packages/core         @direct/core — the application state: types, seed, migrations, every mutation
packages/i18n         @direct/i18n — the en/ar dictionaries and pure string helpers
supabase/migrations   Postgres schema + RLS + RPCs for a later production cutover
design-system/direct-delivery/MASTER.md   UI source of truth
docs/screenshots      Landing / client / driver / admin captures used by the README
.cursor, .agents      Cursor/agent skill packs (not used by Claude Code)
```

npm workspaces (`apps/*`, `packages/*`). All three packages ship **TypeScript source** (`main` and
`types` point at `src/index.ts`); Next compiles them via `transpilePackages` in
`apps/web/next.config.ts`, Metro via `watchFolders` in `apps/mobile/metro.config.js`. Both
tsconfigs map the packages to their source paths and **exclude** the shared `*.test.ts` files.

**Never fork a domain rule between the two clients.** If mobile needs logic the website has, move
it into `packages/*` and have both import it — a fare, freeze, or payment gate that differs
between web and Expo is a bug. The web files that used to own this logic are now thin shims
(`apps/web/src/lib/demo-store.ts`, `place-name.ts`, `driver-route.ts`, `notification-copy.ts`,
`i18n/{en,ar}.ts`); they exist so page imports did not have to change.

`apps/web/AGENTS.md` (and the one-line `apps/web/CLAUDE.md` that imports it) is regenerated by
`next dev` — leave it alone; deleting it from a diff only recreates the change.

## Architecture: there is no backend

**Demo mode is the only mode.** All state lives in `localStorage` under the key
`direct-delivery-demo-v1`. `NEXT_PUBLIC_DEMO_MODE` in `.env.example` is dead — pages talk to the
demo store either way. Supabase SQL exists but **nothing in the UI reads it**.

The only server code is three Whish payment routes under `apps/web/src/app/api/whish/*`.

### Data flow

```
packages/core/src/store.ts         ~2870 lines. The entire "backend": types, seed, migrations,
                                   and every mutation as a PURE function. Zero IO.
apps/web/src/lib/demo-store.ts     Web binding: re-exports core + localStorage load/save/reset.
apps/web/src/lib/store-context.tsx StoreProvider — holds state, calls core, persists.
apps/web/src/lib/auth-context.tsx  AuthProvider — derives user/driver/effectiveRole from the store.
apps/web/src/components/providers.tsx   ThemeProvider > I18nProvider > StoreProvider > AuthProvider

apps/mobile/src/lib/store-context.tsx   Same context surface, AsyncStorage instead of localStorage.
apps/mobile/src/lib/auth-context.tsx    Same derivation, plus `impersonating`.
apps/mobile/app/_layout.tsx             ThemeProvider > I18nProvider > StoreProvider > AuthProvider > ToastProvider
```

`@direct/core` performs **no IO at all** — persistence belongs to each client's provider. That is
the seam the Supabase cutover replaces: swap the provider in both apps, leave the screens alone.

**Every demo-store mutation is `(state, ...args) => { state, error?: string }`** (a few return
plain `DemoState`). They never touch `localStorage` themselves. `StoreProvider.commit()` saves and
sets React state; context methods return the error string (or `undefined`) and pages `toast.error`
it. Follow this shape for anything new.

### Store lifecycle gotchas

- `initialState()` returns a fresh `seed()` and **never reads localStorage** — SSR and the first
  client render must match. Real state loads in a mount effect via `loadState()`.
- `loadState()` runs `migrateState()`, which back-fills every field added since the last release
  (`?? default` for each) and then calls `ensureAdminDriver` → `ensureProtectedAdmin` →
  `ensureOrderNumbers`. **Add a migration line whenever you add a field**, or old saved states break.
- A 5-second interval runs the dispatch pass and `applySubscriptionFreeze`.
  `applySubscriptionFreeze` **returns the same state reference when nothing changed** — this is
  deliberate; allocating a new object every tick would re-render and re-save forever. Preserve that
  pattern in anything that runs on the interval.
- Cross-tab sync via the `storage` event; `refreshFromStorage()` is a polling fallback that only
  commits when driver locations actually moved.

### Auth / impersonation

Sessions are just `state.sessionUserId`. Passwords are plaintext in localStorage — **demo only,
never reuse this shape for production.**

An admin can impersonate via the header "Admin view" select. `viewingAs` (role) and
`viewingAsUserId` (a representative profile of that role) are both set — impersonation must carry
an identity, or every impersonated view still runs under the admin's own id. In `useAuth()`:

- `user` / `driver` / `effectiveRole` reflect the **impersonated** profile.
- `isAdmin` always reflects the **real** signed-in session, so admin chrome keeps working.

Every admin gets a synthetic `owner` driver row (`ensureAdminDriver`) so the driver view has no
restrictions. `useDriverGeolocation` gates on `effectiveRole === "driver"`, not on `driver` being
truthy, so that synthetic row does not start a GPS watch while an admin views as client.

## Domain model (`packages/shared/src/index.ts`)

- `USER_ROLES`: admin, client, business, driver
- `DRIVER_TYPES`: fast, long_distance, trusted, private, owner, medical. `PUBLIC_DRIVER_TYPES`
  hides `medical` in Phase 1. Registration only offers `fast` and `long_distance` — trusted is
  earned through document review, the rest belong to the Direct team.
- `ORDER_TYPES`: normal, long_distance, trusted, private, owner, medical
- `ORDER_STATUSES`: pending → accepted → picked_up → (at_warehouse) → in_transit → arrived →
  awaiting_confirmation → completed; plus cancelled, disputed
- `REVENUE_MODES`: subscription | percentage
- `WHISH_NUMBER = "81848663"` — the company contact number **and** the phone of the protected
  founder admin account.

**`createOrder` hardcodes `order_type: "normal"`.** The long-distance / warehouse-handoff paths
(`at_warehouse`, `long_distance_driver_id`, warehouse products) exist and work in the store and
driver UI, but no client flow currently creates such an order.

`DEFAULT_SETTINGS` / `CompanySettings` hold every tunable: fare bands, per-type multipliers,
subscription prices, grace days, freeze penalty, company percentage, `max_active_orders`, night
surcharge, dispatch radius/growth/timeout, `nearby_radius_km`, `whish_number`. Admin → Settings
edits them live.

## Business rules — read before touching money

### Pricing (`quoteDeliveryPrice`, `order-price.ts`)

1. `interpolateFare` — flat `fare_min_*` from 0 to `fare_min_km` (3 km), linear to `fare_max_km`
   (150 km), capped after. **USD and LBP are independent bands**, so the admin can set each
   currency freely; they are not a conversion of each other.
2. × `multiplierForType` (normal 1, long_distance 1.1, trusted 1.4, private 3.5, owner 1.2,
   medical 2).
3. + night surcharge when `isNightShift` (00:00–06:00 **Asia/Beirut**): `$1` / `89,000 LBP`.
4. Business orders only: `clampQuoteToBusinessCosts` to that business's admin-set min/max.
5. Urgent only: `applyUrgentPricing` ×3 — applied **after** the business clamp, because the ×3 is
   the whole point of the option and a per-business ceiling must not swallow it. It multiplies the
   night surcharge too.

Rounding: `roundUsd` = 2 decimals, `roundLbp` = nearest 1,000 (cash LBP is quoted in thousands).

### Client-set price

A client may pay **more** than the quote (a tip to attract a driver) but **never less**
(`clientPriceError`). The LBP side follows via `scaleLbpToUsd`, keeping the quote's own USD↔LBP
ratio. `quoted_fee_*` is stored alongside `delivery_fee_*` and is the permanent floor.
`updateOrderPrice` only works **while the order is still pending** — once a driver accepts, the pay
they agreed to cannot move under them.

### Revenue split (`splitRevenue`)

The company percentage applies to the **base only**; the night surcharge always stays with the
driver. `createOrder` computes the split forced to `subscription` mode (company cut 0); the real
split is applied at claim time by `applyDriverRevenueSplit`, using **the claiming driver's own**
`revenue_mode` (`driverCompanyPayMode` falls back to company settings).

### Subscription (`subscription.ts`)

Two plans: **daily** ($2 / 24h) and **monthly** ($20 / 30 days).

- `subscriptionEndsAt` extends from `max(now, currentEndsAt)` — renewal is **additive**, paying
  early never discards remaining time; two daily payments stack to 48h.
- `subscriptionGraceMs`: daily gets **zero grace** (freezes the instant 24h ends); monthly keeps
  `settings.grace_days` (5).
- Statuses: `active` → `grace` → `frozen`, plus `pending_payment` for a brand-new driver.
  `grace` does **not** block claiming; `frozen` and `pending_payment` do.
- `applySubscriptionFreeze` skips percentage-mode drivers entirely.

### Commission / percentage mode

The Beirut **work day is 07:00 → 07:00** (`WORK_DAY_START_HOUR`, `workDayStart`).

- `dueNow` = company cuts from completed/disputed orders **before** the current work-day start,
  minus confirmed `kind: "commission"` payments (so it includes unpaid backlog). **Blocks work.**
- `accruingToday` = cuts completed on/after that boundary. **Never blocks**; becomes due at the
  next 07:00.
- **No cron.** `workDayStart()` is re-evaluated on every claim, go-online, and payment check.

`isDriverPaymentBlockingWork` is the single gate: waiver always wins; percentage uses `dueNow`
only; subscription uses `frozen` / `pending_payment`.

### Capacity and dispatch

- `canAcceptAnotherOrder(type, activeCount, max)` — `max_active_orders` defaults to 3, same for
  every driver type. `is_busy` means **"at capacity"**, not "has an order".
- Dispatch (`dispatch.ts` + `demo-store.ts`): a pending order is offered to eligible drivers inside
  a ring starting at 2 km, growing ×1.5 until at least one driver is inside. Drivers inside are
  sorted by pickup distance then dropoff distance. After `dispatch_offer_timeout_sec` (60s) with no
  acceptance, the ring re-expands and previously declined drivers are reconsidered. New eligible
  drivers entering the current radius get added to the round.
- A driver only sees orders **offered to them** (`availableOrdersForDriver`), sorted urgent-first
  then nearest pickup. Admins see all pending orders. Declining keeps the order pending for
  everyone else.
- `tickDispatch` runs on the 5s interval, plus immediately after `createOrder` and `setOnline`.

### Multi-order routing

`buildDriverRoute` → `sequenceStops` (nearest-neighbour construction + 2-opt, both rejecting any
sequence where a drop-off precedes its own pickup). **Google's `optimizeWaypoints` is deliberately
not used** — it reorders freely and would schedule a drop-off before its pickup. Distances are
injected: driving km via the Distance Matrix when Maps is up, haversine otherwise.

### Delivery confirmation

`confirmDelivery` needs **both** sides. The client must pass 1–5 stars; the driver just confirms.
Only when both are true does the order become `completed`, stamp `completed_at`, free the driver's
`is_busy`, and fold the rating into `rating_avg` / `rating_count`.

### Accounts

- **Protected admin**: the profile whose phone equals `WHISH_NUMBER` is the founder account. It
  cannot be removed (`isProtectedAdmin`). `removeAdmin` also refuses self-removal, the last admin,
  and an admin still on an active order.
- Admin actions on drivers: freeze / unfreeze / ban / unban (`setDriverAccountAction`) and payment
  waiver (`setDriverPaymentWaived`). Each sends a typed notification. Unfreezing a driver whose
  subscription is frozen also sets `payment_waived`.
- **Documents**: drivers upload selfie / id / vehicle_registration / driver_license; clients and
  businesses only selfie + id (`allowedDocTypes`). When every required type is approved the account
  becomes `is_trusted` and gets one `docs_approved` notification. An approved selfie doubles as the
  profile photo (`profilePhotoUrl`).
- **Order numbers**: a shared public sequence starting at `1200`, never reused, rendered as
  `#1200`. `ensureOrderNumbers` back-fills any order missing one.

### Privacy helpers

`toPublicContact` exposes **name and phone only** — never email, address, or account internals.
`publicDriverInfo` shares the driver only after acceptance, and keeps admins invisible unless the
client explicitly ordered the Direct team. `publicClientInfo` only answers for the linked driver or
an admin. Use these rather than reaching into `state.profiles` from a page.

## Whish Pay — the hard contract

Read `packages/shared/src/payment-rules.md`. It is the single source of truth for web **and** the
future Expo app; Expo must import the helpers, not re-implement them.

Drivers pay via **merchant collect**, not a freeform P2P transfer.

**Unlock only when `collectStatus === "success"` (exact string).** Use `isWhishCollectPaid`.
The following must **never** unlock:

- opening the pay URL, or leaving the Whish page without paying
- `pending`, `failed`, `unknown`, empty, or any other casing including `"Success"`
- success/failure **callback or redirect query params** on their own
- showing or matching the company Whish number

Always re-verify `POST /payment/collect/status` by `externalId` before confirming a transaction.
Amounts are capped at `WHISH_MAX_AMOUNT_USD` = 10,000 (subscription + freeze penalty + a day's
commission backlog must all fit).

Server pieces: `lib/whish-server.ts` (env, origin resolution, `fetchCollectStatus`), routes under
`app/api/whish/`. Client: `hooks/use-whish-collect.ts` (create → open → poll every 4s → confirm)
and `lib/whish-collect.ts` (return-param handling via sessionStorage).

**Redirect origin**: when `WHISH_WEBSITE_URL` is set, redirects use that origin and deliberately
ignore the request `Host` / `X-Forwarded-*` headers, so a forged header cannot bounce the driver to
another site.

**Fallback**: with `WHISH_CHANNEL` / `WHISH_SECRET` unset, `/api/whish/create` returns
`{configured: false}` and the UI must not pretend the collect succeeded — the driver uses **"I
already paid"**, which logs a pending manual tx for an admin to confirm in Admin → Budget → Whish.

Env lives in `apps/web/.env.local` (copy from `.env.example`). Sandbox base:
`https://lb.sandbox.whish.money/itel-service/api`.

**Mobile has no second collect surface.** `apps/mobile/src/lib/whish.ts` posts to the deployed
web origin (`EXPO_PUBLIC_WEB_URL`) and `hooks/use-whish-collect.ts` runs create → open in
`expo-web-browser` → poll every 4s → confirm. The channel and secret never ship in the Expo
bundle. Unlock requires the status re-check to return paid **and** `isWhishCollectPaid(status)`;
closing the browser, a redirect, or a deep-link parameter unlocks nothing.

## Maps

Optional. Set `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY`; without it panels still render markers and route
hints from an offline placeholder.

- `components/maps-config.ts` hooks `window.gm_authFailure` and remembers the failure in
  `sessionStorage` for the session, so later loads skip Google entirely.
- `components/maps-provider.tsx` is the single loader. `useMapsAvailable()` is the only correct way
  to ask "can I render Google widgets here". `APIProvider` is keyed on `lang` and passes
  `language={lang} region="LB"`, which is what makes Google itself return Arabic place names.
- `lib/route-distance.ts` — Distance Matrix with a 45s cache and 25-per-batch chunking, haversine
  fallback on any error. Used by both fare quotes and dispatch.
- `place-name.ts` (now in `@direct/core`) — **never returns raw coordinates.** `locationLabel()`
  normalizes anything into a human place name, falling back to the nearest of ~23 named Lebanese
  areas (within 18 km) or "Pinned location". Pass `lang` on display surfaces, omit it when
  normalizing for storage.

On mobile: `react-native-maps`. iOS falls back to Apple Maps and always renders; Android is
Google-only, so with no key `mapsAvailable()` is false and the panels degrade to a labelled list —
the same trade the web placeholder makes. `apps/mobile/src/lib/route-distance.ts` mirrors the web
cache and fallback but calls the Distance Matrix **REST** endpoint, since the Maps JS SDK does not
exist on native.

## i18n and RTL

`lib/i18n/{en,ar,index}.tsx`. Two dictionaries with the **same shape** — sections: `common`,
`roles`, `docStatus`, `notify`, `orderStatus`, `nav`, `home`, `auth`, `order`, `client`, `driver`,
`profile`, `admin`. Adding a key means adding it to both.

- `fmt(template, vars)` substitutes `{placeholders}`.
- Language persists under `direct-lang` (localStorage on web, AsyncStorage in Expo); the web
  provider sets `document.documentElement.lang` and `dir`.
- **On native, switching language relaunches the app.** React Native only mirrors layout after
  `I18nManager.forceRTL` and a restart, so `apps/mobile/src/lib/i18n.tsx` flips the flag and calls
  `Updates.reloadAsync()`. Without the relaunch you get Arabic strings in a left-to-right layout.
- Notifications are **stored in English** but every kind except `generic` re-renders from the
  dictionary via `lib/notification-copy.ts`, so an Arabic reader sees Arabic whatever language it
  was written in.
- Arabic typography is corrected in `globals.css`: IBM Plex Sans Arabic (an Uber Move Arabic
  stand-in), letter-spacing zeroed on every `tracking-*` utility, `uppercase` neutralized,
  line-heights normalized.
- **Use logical CSS properties everywhere** (`start`/`end`, `ps-`/`pe-`, `text-start`) — the app
  flips to RTL wholesale.

## Design system

`design-system/direct-delivery/MASTER.md` is the source of truth; tokens live in
`apps/web/src/app/globals.css`.

Uber-style **monochrome**: surfaces are shades of white (light) / black (dark), primary buttons are
black-on-white and white-on-black. Brand blue `#2563eb` (`#4d82f3` dark) is an **accent only** —
links, active nav, focus rings, map markers. Gold `#d4af37` is **decorative only** — thin accent
lines, logo glow — never a background, button, or text block.

shadcn/ui with the `base-nova` style on top of `@base-ui/react` (note: Base UI, not Radix — buttons
take a `render` prop; see `components/link-button.tsx`). Icons are **Lucide only — never emoji as
icons**. Utilities: `.touch-target` (≥44px), `.text-easy`, `.heading-easy`, `.logo-glow`.

Before shipping UI: contrast ≥4.5:1, visible focus rings, 44px touch targets, transitions
150–300ms, `prefers-reduced-motion` honored, no horizontal scroll at 375px.

**On mobile** the same hex values are restated as plain objects in `apps/mobile/src/theme/tokens.ts`
(React Native has no CSS variables) — keep the two in step. Plus Jakarta Sans and IBM Plex Sans
Arabic load through `@expo-google-fonts`; every string goes through `components/ui/text.tsx`, which
is the one place that knows which family and tracking the active language uses. Weight always
resolves to a real family name, never a `fontWeight` React Native would synthesise.

Mobile-specific conventions, all deliberate:
- Bottom sheets replace centred dialogs; a phone's bottom edge is the one-handed region.
- A primary action is pinned below the scroll area (`Screen`'s `footer` slot).
- Never nest a pressable inside a pressable — screen readers announce one confusing target and
  react-native-web emits invalid DOM. `OrderCard` renders its actions outside the tappable region.
- Use logical styles (`marginStart`, `paddingEnd`, `textAlign: "left"`); they mirror for free.

## Supabase (schema only, not wired)

`supabase/migrations/` applied in order (`supabase db push`, or `npm run db:reset` locally). Never
apply only the init migration.

Tables: profiles, drivers, driver_documents, warehouses, warehouse_products, company_settings
(single row, `id = 1`), orders, order_events, order_confirmations, ratings, reports,
driver_locations, private_checkins, subscriptions, whish_transactions. RLS on all of them.

RPCs: `nearby_drivers(lat, lng, radius, driver_type)`, `claim_order(order_id, driver_id)` (atomic
first-accept), `handle_new_user()` (profile bootstrap trigger on `auth.users`), `email_for_phone()`.

Admin identity comes from the **JWT** — `auth.jwt() -> 'app_metadata' ->> 'role' = 'admin'`, not
`profiles.role`. Promote with `supabase/seed_admin.sql`. `claim_order` refuses when
`p_driver_id != auth.uid()`.

**Known drift** (documented in the 2026-09-11 migration header, deliberately out of scope): the SQL
has no `kind` on `whish_transactions`, and no `admin_frozen` / `banned` / `payment_waived` /
`revenue_mode` columns on `drivers`. The demo store has all of them. Any production cutover has to
close this gap.

## Conventions

- Pages are `"use client"` almost everywhere — the app is a client-state SPA on the App Router.
- Domain logic that mobile will also need goes in `packages/shared`; anything web-only
  (localStorage, Google Maps, React) stays in `apps/web/src/lib`.
- Pure functions in `demo-store.ts`, side effects in `store-context.tsx`. Never call `saveState`
  from a page.
- `toSorted` / `toReversed` are used freely — never mutate arrays in place inside a
  reducer-style function. **Hermes has neither**, so `apps/mobile/src/lib/polyfills.ts`
  installs them and `app/_layout.tsx` imports it first. Reaching for another ES2023
  change-array-by-copy method (`toSpliced`, `with`) means adding it there too, or the
  native app throws `undefined is not a function` mid-render.
- Comments in this codebase explain **why**, not what, and they are dense around the payment,
  dispatch, and hydration code. Match that when editing those files.
- Money is always dual-currency: show `formatDeliveryCash(usd, lbp)` → `$5.00 · 890,000 LBP`.
- Hydration: anything derived from `localStorage`, `sessionStorage`, or Google Maps must be gated
  behind a mount effect so SSR and the first client paint match.
